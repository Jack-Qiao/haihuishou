# 竞价侠 - 需求文档

## 1. 项目概述

### 1.1 产品名称
竞价侠（biddingHero）

### 1.2 产品目标
基于「竞价侠」平台接口，为报价师提供 Web 端的商品竞价能力：登录后可查询可竞价商品列表、查看商品详情、直接对商品出价、修改报价、取消抢单，提升电脑端的操作效率。

### 1.3 目标用户
- 使用竞价侠平台的报价师/回收商。

### 1.4 使用场景
- 在浏览器中完成登录、列表刷新、查看详情、出价、修改报价等操作。
- 支持打包为单机可执行程序，免安装 Python 运行。

## 2. 功能需求

### 2.1 登录与登出

| 需求项 | 描述 |
|--------|------|
| 登录 | 用户输入手机号、密码，调用 `POST /api/base/login/`；成功后服务端保存 token、userId（Session）。 |
| 登出 | 清除 Session，返回登录页。 |
| 登录态校验 | `GET /api/status` 判断是否已登录；已登录则拉取用户信息展示。 |

### 2.2 用户信息展示

| 需求项 | 描述 |
|--------|------|
| 获取用户信息 | `GET /api/base/users/getMyInfo/`（登录后自动调用）。 |
| 展示位置 | 页面右上角展示「已登录：<用户名>」。 |

### 2.3 竞价列表（可竞价商品）

| 需求项 | 描述 |
|--------|------|
| 数据来源 | `GET /api/base/orders/auction_list/`（Query: pageIndex, pageSize）。 |
| 列表内容 | 至少展示：订单 ID、产品名称（`model_name`）、类目（`cate_name`）、状态（是否在报价中）、操作。 |
| 操作按钮 | 每一行有「查看详情」「出价」两个按钮；如果该商品已在「报价中列表」，另外展示「取消」按钮。 |
| 直接出价 | 竞价侠没有独立的「抢单」按钮，可以直接点击「出价」提交报价（`POST /api/base/orders/{orderId}/place_bid/`）。 |
| 分页 | 每页支持 20 / 50 / 100 / 500，可上下翻页。 |
| 状态标签 | 若商品 ID 命中「报价中列表」（`grab_order_list`）中的任一项，则渲染「报价中」标签并高亮该行。 |

### 2.4 查看详情 = 抢单

| 需求项 | 描述 |
|--------|------|
| 触发 | 点击列表某一行的「查看详情」按钮。 |
| 平台行为 | 调用 `GET /api/base/orders/{orderId}/detail_info/` 会在服务端将该商品加入到当前用户的「报价中列表」（`grab_order_list`）。 |
| 前端行为 | 拉取详情后再次调用 `GET /api/base/orders/grab_order_list/` 刷新本地缓存的报价中 ID 列表，并重绘列表使「报价中」标签生效。 |

### 2.5 报价数据列表展示规则

| 需求项 | 描述 |
|--------|------|
| 规则 | 拿到「报价中列表」（`grab_order_list`）返回的报价商品 id 列表后，需要通过对比列表中是否包含本条商品的 id 才展示「报价数据列表详情」。 |
| 未命中 | 未命中时详情窗口内不展示报价数据列表模块；仅展示商品基础详情。 |
| 已命中 | 详情窗口内额外展示当前所有报价数据（金额、报价人、时间等，字段以详情接口返回为准）。 |

### 2.6 出价 / 修改报价弹窗

| 需求项 | 描述 |
|--------|------|
| 弹窗标题 | 「提交报价」或「商品详情」（当用户只是查看时）。 |
| 展示项 | 产品名称、订单 ID（只读）；商品详情摘要；报价数据列表（若命中报价中列表）；报价金额输入框。 |
| 提交校验 | 报价金额必填、≥ 1。 |
| 提交逻辑 | 调用 `POST /api/base/orders/{orderId}/place_bid/`，body：`{ bid_amount }`。修改报价复用同一接口。 |
| 提交后 | 关闭弹窗，刷新列表和已报价列表。 |

### 2.7 取消抢单

| 需求项 | 描述 |
|--------|------|
| 触发 | 列表中「报价中」状态的商品行会出现「取消」按钮，点击后调用 `POST /api/base/orders/{orderId}/cancel_grab_order/`。 |
| 成功后 | 该商品从「报价中列表」移除，刷新列表。 |

### 2.8 已报价列表 Tab

| 需求项 | 描述 |
|--------|------|
| 数据来源 | `GET /api/base/bid-records/my_bids/`（Query: pageIndex, pageSize, status, created_at_after, created_at_before）。 |
| 筛选 | 状态（bidding / win / lose / 全部）、开始日期、结束日期、每页条数。 |
| 列表内容 | 订单 ID、产品名称、报价金额、状态、操作（查看详情 / 修改报价）。 |

### 2.9 其他交互

| 需求项 | 描述 |
|--------|------|
| Toast | 出价成功 / 失败通过顶部 Toast 提示。 |
| 错误提示 | 接口错误时在对应区块或弹窗内展示错误信息。 |

### 2.10 自动抢单（定时任务）

| 需求项 | 描述 |
|--------|------|
| 目标 | 根据用户预设的匹配条件（品类 / 品牌 / 货源(厂商) / 价格范围 / 最大金额 / 机型+存储 + 9 档成色报价 + 保底价），自动执行「拉取列表 → 匹配条件 → 查看详情（自动进入抢单）→ 出价」的循环。 |
| 数据来源 | 本地 `localStorage`：`biddinghero_scheduled_tasks`（任务数组）、`biddinghero_schedule_max_amount`（全局最大金额）。 |
| 执行入口 | 手动「运行一次」或 1/2/3/5/10/30/60 秒/次频率轮询；一键全部启动 / 全部暂停 / 全部删除。 |
| 匹配规则 | 前端过滤 `cate_name / brand_name / order_channel_name / bid_amount`；后端 per-candidate 拉验机报告，从 `report_data.inspection_items` 里提取内存组合成 `8+128g` 归一化字符串；按 (机型, 存储) 匹配条件行；按 `machine_level_name` 取对应成色列价，若为空则回落 `floorPrice`（保底价）。 |
| 出价约束 | 单笔报价 ≤ 「最大金额」全局设置；若单笔超限则跳过。已有自己报价的订单不再改价（避免覆盖手动改价）。 |
| 价格 Excel | 支持 xlsx 导入导出，列头：品牌 / 机型 / 内存 / 全新 / 靓机 / 小花 / 大花 / 外爆 / 内爆 / 功能异常 / 维修更换 / 无法开机 / 保底价。 |
| 验机报告展示 | 查看详情弹窗内额外渲染验机报告：品牌 / 型号 / 内存 / 购买渠道 / 颜色 / IMEI 头部字段 + 全部检测项两列铺开。 |

## 3. 接口需求

### 3.1 平台侧接口（参考「接口文档说明」）

| 用途 | 方法 | 路径 |
|------|------|------|
| 登录 | POST | `/api/base/login/` |
| 用户信息 | GET | `/api/base/users/getMyInfo/` |
| 查询列表 | GET | `/api/base/orders/auction_list/` |
| 报价中列表 | GET | `/api/base/orders/grab_order_list/` |
| 已报价列表 | GET | `/api/base/bid-records/my_bids/` |
| 商品详情 | GET | `/api/base/orders/{orderId}/detail_info/` |
| 验机报告 | GET | `/api/base/orders/{orderId}/order_report_frontend/` |
| 出价 | POST | `/api/base/orders/{orderId}/place_bid/` |
| 取消抢单 | POST | `/api/base/orders/{orderId}/cancel_grab_order/` |

### 3.2 本系统 Web API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 单页 HTML |
| POST | `/api/login` | 登录 |
| POST | `/api/logout` | 登出 |
| GET | `/api/status` | 登录态 |
| GET | `/api/user-info` | 当前用户信息 |
| GET/POST | `/api/order-list` | 竞价列表 |
| GET | `/api/grab-order-list` | 报价中列表（含纯 id 数组供前端对比） |
| GET | `/api/my-bids` | 已报价列表 |
| GET | `/api/order-detail?orderId=` | 商品详情（同时返回最新 grab_order 列表、ids 与验机报告 `report`） |
| GET | `/api/order-report?orderId=` | 验机报告（inspection_items） |
| POST | `/api/place-bid` | 出价 |
| POST | `/api/cancel-grab-order` | 取消抢单 |
| POST | `/api/execute-task` | 执行自动抢单任务（列表→报告→匹配→详情→出价） |
| POST | `/api/import-price-list` | 导入 xlsx 价格表 |
| POST | `/api/export-price-list` | 导出 xlsx 价格表 |

## 4. 非功能需求

### 4.1 运行环境
- Python 3.8+；依赖见 `requirements.txt`（Flask、requests）。
- 默认地址：http://127.0.0.1:5070。

### 4.2 部署与分发
- 支持 PyInstaller 打包为单文件可执行程序（`biddinghero.spec`）。

### 4.3 安全与合规
- 仅用于学习或经授权的调试。
- 账号密码请通过登录页面输入，不写入仓库。

---

## 5. 与嗨回收工具的关键差异

1. **中文名**：本工具中文名为「竞价侠」。
2. **无独立抢单操作**：可直接在列表中出价。
3. **查看详情 = 抢单**：详情接口会将商品加入报价中列表。
4. **报价数据展示条件**：只有当商品出现在报价中列表（`grab_order_list`）时，才在详情弹窗内展示报价数据列表详情。
